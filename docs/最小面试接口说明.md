# 最小面试接口说明

## 1. 目标

本模块将已有的知识库、RAG 和文本面试流程封装成可调用的 HTTP 接口，方便后续：

- 前端页面联调
- 语音模块接入
- 报告生成模块接入
- 多岗位统一接入

当前接口为最小可用版本，重点是把流程跑通，而不是一次性做复杂架构。

---

## 2. 启动方式

脚本位置：

- `D:\AI_Interview_Project\scripts\interview_api.py`

启动命令：

```powershell
D:\AI_Interview_Project\scripts\.venv\Scripts\python.exe D:\AI_Interview_Project\scripts\interview_api.py `
  --host 127.0.0.1 `
  --port 8010
```

可选参数：

- `--db-dir`
- `--runtime-dir`
- `--embedding-model`
- `--local-model-only`

## 3. 当前接口列表

### `GET /health`

用于健康检查。

示例返回：

```json
{
  "ok": true,
  "service": "minimal_interview_api",
  "roles": ["java_backend", "web_frontend"]
}
```

### `GET /roles`

用于获取当前支持的岗位列表。

### `POST /interview/start`

用于开始一场面试。

请求体示例：

```json
{
  "role": "java_backend",
  "topic": "collection",
  "difficulty": "medium",
  "question_query": "HashMap"
}
```

### `POST /interview/answer`

用于提交当前题目的回答。

请求体示例：

```json
{
  "session_id": "d173bb7f6ce4",
  "answer": "HashMap 底层是数组、链表和红黑树..."
}
```

### `POST /interview/finish`

用于结束面试并获取总结。

请求体示例：

```json
{
  "session_id": "d173bb7f6ce4"
}
```

### `POST /report/generate`

用于生成结构化面试报告。

请求体示例：

```json
{
  "session_id": "d173bb7f6ce4"
}
```

### `GET /report/{session_id}`

用于直接获取某场面试的结构化报告。

### `POST /report/view`

用于获取适合前端报告页直接消费的 `view_model`。

### `GET /report/view/{session_id}`

用于直接获取某场面试的报告页 ViewModel。

### `GET /interview/session/{session_id}`

用于查看当前 session 原始状态。

## 4. 当前接口行为

### 4.1 首题获取策略

接口在开始面试时会优先尝试：

1. 从 Chroma collection 检索首题
2. 检索失败时回退到本地 Markdown 主知识库

因此即使本地向量库环境不稳定，也不会阻断前端联调。

### 4.2 session 存储

当前 session 保存在本地：

- `D:\AI_Interview_Project\runtime\sessions\`

每个 session 是一个 JSON 文件。

这适合当前比赛开发阶段，后续可替换为数据库或缓存。

---

## 5. 当前适用场景

这一版接口已经足够支撑：

- 文本版模拟面试页面
- 多岗位切换
- 回答提交与即时反馈
- 面试记录查看
- 报告页联调
- 导出 Markdown 报告
- 报告页直接渲染 ViewModel
