# AI模拟面试与能力提升平台实施路线图

## 1. 项目目标

围绕比赛题目，完成一个面向计算机相关专业学生的 AI 模拟面试与能力提升平台，满足以下核心能力：

- 岗位化题库与知识库
- 多轮模拟面试
- 动态追问
- 回答评估
- 报告生成
- 个性化提升建议
- 面试历史记录与成长可视化

当前已完成基础较好的部分是：

- Java 后端岗位主知识库标准化
- Java 岗位 RAG 入库脚本
- Java 岗位检索验证脚本

后续应基于现有成果，扩展成完整平台，而不是推倒重来。

---

## 2. 当前成果评估

### 2.1 已经做得比较好的部分

- 已经完成 `Java后端主知识库-标准化面试题库.md`，并扩充到 100 题，具备展示价值。
- 已经为主库建立明确格式规范，后续多人协作时可保持结构稳定。
- `ingest_data.py` 已支持：
  - 指定 collection
  - 指定本地 embedding 模型
  - `--local-model-only`
  - `--files` 精准入库
  - 对 `## Qxxx` 单题结构做专门切分
  - 单题级 metadata 抽取
- `query_test.py` 已能输出检索结果的关键 metadata，方便做 RAG 调优。

### 2.2 当前还缺的关键部分

- 还缺第二岗位知识库，暂时不满足“至少两种岗位”的赛题要求。
- 还缺统一的后端服务层，当前主要是离线脚本，未形成完整系统接口。
- 还缺面试流程编排模块：开场、出题、追问、结束、总结。
- 还缺回答评估引擎：技术正确性、逻辑性、岗位匹配度、多维评分。
- 还缺语音链路：ASR、TTS、表达分析。
- 还缺前端交互界面与历史记录看板。
- 还缺项目材料产出链：项目简介、详细方案、PPT、演示视频脚本。

### 2.3 对当前阶段的结论

你负责的 Java 岗位 RAG 引擎已经不是“刚起步”，而是已经进入“可作为平台底座”的阶段。

更准确地说：

- 现在不是缺一个脚本
- 而是缺把“Java RAG 底座”接到“完整面试产品链路”上

## 3. 总体实施策略

整个项目建议分成 7 个阶段，每个阶段都产出可演示结果。

### 阶段 1：夯实 RAG 基座

目标：

- 把 Java 岗位知识库、入库、检索、检索质量验证做成稳定底座

产出：

- Java 主知识库
- Java 补充知识库方案
- 稳定入库脚本
- 稳定检索验证脚本
- 检索测试用例

### 阶段 2：补齐第二岗位

目标：

- 至少新增一个岗位，满足赛题要求

建议岗位：

- Web 前端

原因：

- 与 Java 后端对比明显，便于展示“岗位差异化”
- 前端和后端面试重点差异大，评委更容易感知产品价值

产出：

- `data/web_frontend/` 结构化主知识库
- 与 Java 共用的入库脚本
- 独立 collection 或统一多岗位 collection 方案

### 阶段 3：实现面试流程引擎

目标：

- 把“检索”升级成“可进行模拟面试的对话流程”

核心流程：

- 选择岗位
- 选择难度
- 生成首题
- 接收回答
- 追问
- 多轮面试
- 结束总结

产出：

- 面试会话状态机
- 出题策略
- 追问策略
- 会话上下文结构

### 阶段 4：实现评估与反馈引擎

目标：

- 从“能问题”升级到“能评估”

评分维度建议：

- 技术正确性
- 回答完整性
- 知识深度
- 逻辑清晰度
- 岗位匹配度
- 沟通表达

产出：

- 评分 JSON 结构
- 评估 Prompt 模板
- 综合反馈报告模板
- 改进建议模板

### 阶段 5：接入语音与多模态

目标：

- 满足赛题中的语音交互要求

实现方向：

- ASR：语音转文字
- TTS：AI 面试官播报问题
- 表达分析：语速、停顿、清晰度、自信度

产出：

- 语音输入链路
- 语音输出链路
- 表达分析结果结构

### 阶段 6：搭建可演示前后端系统

目标：

- 做出真正可演示的软件界面

建议页面：

- 首页/岗位选择页
- 模拟面试页
- 面试报告页
- 历史记录页
- 成长曲线页

### 阶段 7：完善比赛交付材料

目标：

- 让技术成果转化为评审可理解的材料

产出：

- 项目概要介绍
- 项目详细方案
- PPT
- 演示视频脚本
- 本地知识库资料说明

## 5. 当前建议的第一优先级

接下来最优先做的不是立刻上语音，也不是先做炫界面，而是：

- 把 Java RAG 基座彻底收尾
- 同时规划第二岗位知识库
- 然后立刻进入“面试流程引擎”

原因：

- 评委更看重完整产品链路
- Java 岗位 RAG 单点再继续精修，边际收益会下降
- 没有第二岗位和流程引擎，系统仍然像“知识库脚本”而不像“AI 面试平台”
