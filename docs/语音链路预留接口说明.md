# 语音链路预留接口说明

本文档说明当前最小语音链路。当前后端不依赖真实 ASR/TTS 服务，默认使用 `stub` 实现；前端已经接入浏览器 Web Speech API，可以在 Chrome/Edge 中通过麦克风进行真实语音输入，并把浏览器转写文本提交到后端评分链路。

## 目标

- 支持语音输入接口预留。
- 支持语音转文字结果结构。
- 支持 AI 面试官播报接口预留。
- 支持表达分析结果结构。
- 打通语音答题与现有文本面试、评分、报告 ViewModel。

## 运行目录

默认语音运行产物目录：

```text
D:\AI_Interview_Project\runtime\audio
```

接口服务可通过参数覆盖：

```powershell
python -X utf8 scripts\interview_api.py --audio-dir D:\AI_Interview_Project\runtime\audio
```

## 新增模块

```text
D:\AI_Interview_Project\scripts\speech_io.py
```

当前包含：

- `transcribe_audio_stub`：语音转文字占位实现。
- `synthesize_speech_stub`：面试官 TTS 播报占位实现。
- `analyze_expression_stub`：表达分析规则占位实现。
- `speech_capabilities`：返回当前语音能力开关与字段约定。

## 前端真实语音输入

最小前端页面已支持浏览器麦克风语音输入：

```text
D:\AI_Interview_Project\webapp\index.html
D:\AI_Interview_Project\webapp\app.js
D:\AI_Interview_Project\webapp\styles.css
```

使用方式：

1. 启动接口服务并打开 `http://127.0.0.1:8010/app`。
2. 使用 Chrome 或 Edge 浏览器。
3. 开始一场面试。
4. 点击“开始录音”，允许麦克风权限。
5. 正常口头作答，页面会实时显示语音转写。
6. 点击“使用语音提交”，系统会调用 `/interview/answer-audio` 完成评分、追问和表达分析。

说明：

- 真实转写发生在浏览器侧，由 `SpeechRecognition` / `webkitSpeechRecognition` 提供。
- 后端 `/interview/answer-audio` 当前接收浏览器转写后的 `text_hint`，再进入现有面试评分链路。
- 如果浏览器不支持 Web Speech API，页面会自动提示继续使用文本输入。

## 新增接口

### GET /speech/capabilities

返回当前语音能力：

```json
{
  "provider": "stub",
  "asr": {
    "enabled": true,
    "mode": "stub"
  },
  "tts": {
    "enabled": true,
    "mode": "stub"
  },
  "expression_analysis": {
    "enabled": true,
    "mode": "rule_stub"
  }
}
```

`GET /health` 也会附带 `speech` 字段，方便前端启动时一次性探测。

### POST /speech/transcribe

语音转文字预留接口。当前不调用真实 ASR，优先使用 `text_hint` 或 `manual_text` 作为转写结果。

请求示例：

```json
{
  "session_id": "demo_session",
  "audio_base64": "",
  "audio_format": "webm",
  "duration_ms": 12000,
  "language": "zh-CN",
  "text_hint": "HashMap 底层主要由数组、链表和红黑树组成。"
}
```

响应核心字段：

```json
{
  "provider": "stub",
  "status": "completed",
  "transcript": "HashMap 底层主要由数组、链表和红黑树组成。",
  "confidence": 0.92,
  "segments": [],
  "audio_file": "",
  "next_action": "submit_to_interview_answer"
}
```

### POST /interview/answer-audio

语音答题接口。它会完成：

1. 调用语音转文字占位逻辑。
2. 调用表达分析占位逻辑。
3. 把 transcript 作为回答提交到现有 `answer_interview`。
4. 在 session history 中记录 `answer_source=speech`、`speech_result`、`expression_analysis`。

请求示例：

```json
{
  "session_id": "真实 session_id",
  "text_hint": "HashMap 可以通过扰动函数和链表转红黑树减少冲突带来的性能问题。",
  "duration_ms": 15000,
  "language": "zh-CN"
}
```

响应会保留原文本答题接口的字段，并额外返回：

- `speech_result`
- `expression_analysis`

### POST /speech/synthesize

AI 面试官播报预留接口。当前不生成真实音频，只返回 text-only 结构，前端可以先展示字幕或使用浏览器本地语音能力播报。

请求示例：

```json
{
  "text": "请你说明一下 HashMap 的底层结构。",
  "voice": "interviewer_female_zh",
  "format": "mp3"
}
```

响应核心字段：

```json
{
  "provider": "stub",
  "status": "text_only",
  "text": "请你说明一下 HashMap 的底层结构。",
  "audio_url": "",
  "audio_base64": "",
  "captions": []
}
```

### POST /speech/analyze-expression

表达分析预留接口。当前按文本做规则型估计，输出：

- `fluency`
- `clarity`
- `pace`
- `confidence`

请求示例：

```json
{
  "transcript": "首先 HashMap 底层是数组加链表加红黑树，其次它通过 hash 扰动和扩容控制冲突。",
  "duration_ms": 12000
}
```

## 报告衔接

结构化报告新增：

```json
{
  "expression_summary": {
    "enabled": true,
    "rounds": 1,
    "average_metrics": {
      "fluency": 9.0,
      "clarity": 6.8,
      "pace": 8.5,
      "confidence": 8.1
    },
    "suggestions": []
  }
}
```

报告页 ViewModel 新增：

```json
{
  "expression": {
    "enabled": true,
    "rounds": 1,
    "average_metrics": {}
  }
}
```

前端后续可以在报告页增加“表达能力”卡片，直接读取 `view_model.expression`。

## 后续替换真实服务的位置

后续接真实服务时，优先只替换：

```text
scripts\speech_io.py
```

建议保留现有响应结构，避免影响：

- `interview_api.py`
- `interview_flow.py`
- 前端报告页 ViewModel
