# 前端报告页对接说明

## 1. 目标

本说明用于帮助前端同学直接消费面试报告接口，不需要再自行从底层 session 或原始评估结果里拼字段。

推荐优先使用：

- `POST /report/view`

或者：

- `GET /report/view/{session_id}`

这两个接口会直接返回适合报告页展示的 `view_model`。

---

## 2. 推荐页面结构

当前报告页建议拆成以下区域：

1. 顶部摘要区
2. 维度得分卡片区
3. 雷达图区
4. 亮点与待改进区
5. 逐题回顾区
6. 下一步行动计划区
7. 推荐补强资源区

---

## 3. view_model 结构

接口返回的核心字段为：

```json
{
  "view_model": {
    "session_id": "d173bb7f6ce4",
    "role": "java_backend",
    "role_label": "Java后端开发工程师",
    "generated_at": "2026-05-07T15:49:22",
    "report_file": "D:\\AI_Interview_Project\\runtime\\reports\\d173bb7f6ce4_java_backend_report.md",
    "summary": {
      "overall_score": 5.8,
      "rounds": 1,
      "text": "本次 Java后端开发工程师 模拟面试共完成 1 轮，综合得分 5.8/10。当前最需要提升的维度是：completeness、logic_clarity。"
    },
    "score_cards": [],
    "radar": {
      "indicators": []
    },
    "highlights": [],
    "improvements": [],
    "rounds_detail": [],
    "action_plan": [],
    "recommended_resources": []
  }
}
```

---

## 4. 字段说明

### `summary`

用于页面顶部摘要卡片。

- `overall_score`
- `rounds`
- `text`

### `score_cards`

用于维度分数卡片展示。

每一项包含：

- `key`
- `label`
- `score`
- `max_score`

### `radar.indicators`

用于雷达图展示。

每一项包含：

- `name`
- `key`
- `value`
- `max`

### `highlights`

用于“表现亮点”卡片列表。

### `improvements`

用于“待改进点”卡片列表。

### `rounds_detail`

用于逐题回顾列表。

每一项包含：

- `question_id`
- `question`
- `score`
- `follow_up`
- `highlights`
- `improvements`

### `action_plan`

用于“下一步行动计划”有序列表。

### `recommended_resources`

用于“推荐补强方向”列表。

---

## 5. 前端使用建议

### 摘要区

展示：

- 岗位名称
- 综合得分
- 面试轮次
- 一句话总结

### 图表区

建议：

- 使用雷达图展示维度能力
- 使用分数卡片展示每项得分

### 逐题回顾区

建议：

- 每题一个折叠卡片
- 展示题目、得分、追问、亮点、改进项

### 行动计划区

建议：

- 直接按步骤列表展示

---

## 6. 当前最推荐调用方式

### 生成并获取报告页数据

```http
POST /report/view
Content-Type: application/json

{
  "session_id": "d173bb7f6ce4"
}
```

### 根据 session 直接读取报告页数据

```http
GET /report/view/d173bb7f6ce4
```

---

## 7. 说明

当前 `view_model` 已经尽量贴近前端页面展示需求。

后续如果页面结构发生变化，优先改这里的 ViewModel 生成逻辑，而不是让前端到处兼容底层数据。
